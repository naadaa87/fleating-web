# 플리팅 서비스 확장 구조

## 1. 현재 상태

현재 프로젝트는 React + Vite 기반 SPA이며, 별도 서버 없이 화면과 주요 사용자 흐름을 확인하기 위한 MVP입니다. 데이터는 `src/data.ts`, 사용자 시연 데이터는 브라우저 localStorage에 있습니다.

## 2. 권장 백엔드 경계

프론트엔드는 아래 API 경계를 기준으로 교체할 수 있습니다.

- `/auth`: 로그인, 소셜로그인, 휴대전화·이메일 인증
- `/markets`: 행사 등록, 검색, 상세, 수정이력, 공식출처
- `/recruitments`: 모집공고, 지원서, 선정·대기·취소
- `/sellers`: 셀러 프로필, 외부채널, 참여이력, 인증
- `/feeds`: 셀러 활동 피드, 좋아요, 댓글, 신고
- `/events`: 쿠폰, 스탬프, QR 체크인, 추첨
- `/notifications`: 모집마감, 선정결과, 일정변경, 팔로우 알림
- `/payments`: 참가비, 취소·환불, 정산
- `/admin`: 콘텐츠 검수, 중복통합, 신고, 제재, 통계

## 3. 핵심 데이터 모델

- User: 계정, 역할, 인증상태, 관심지역·카테고리
- Organizer: 주최자 정보, 사업자·단체 인증, 개최이력
- Market: 일정, 장소, 우천정책, 프로그램, 출처, 수정이력
- Recruitment: 모집기간, 분야, 정원, 참가비, 제공집기, 정책
- Application: 셀러 지원서, 추가질문, 상태, 메모, 결제상태
- SellerProfile: 브랜드, 대표상품, 외부채널, 인증, 참여이력
- Participation: 행사-셀러 연결, 체크인, 노쇼, 후기권한
- FeedPost: 출점·신상품·제작·이벤트·후기 유형
- Interaction: 관심등록, 좋아요, 댓글, 팔로우, 신고
- Notification: 대상, 유형, 발송상태, 읽음상태

## 4. Cloudflare 기반 확장안

- 정적 프론트엔드: Cloudflare Pages
- API: Cloudflare Workers 또는 별도 서버
- 관계형 데이터: Cloudflare D1 또는 PostgreSQL 계열 서비스
- 이미지: Cloudflare R2 + Images
- 로그인·권한: 외부 인증서비스 또는 자체 OAuth/JWT
- 반복·예약 알림: Queues, Cron Triggers
- 실시간 기능: Durable Objects 또는 별도 실시간 서비스

특정 제품 선택은 예상 트래픽, 개발 인력, 결제·정산 범위와 개인정보 처리정책을 확정한 뒤 결정해야 합니다.

## 5. 앱 확장

웹과 앱이 같은 API·데이터 모델을 공유하도록 구성합니다.

- 빠른 전환: React Native 또는 Expo
- 웹 코드 재사용보다 UX 일관성과 API 공유를 우선
- 앱 우선 기능: 푸시알림, QR 체크인, 위치기반 탐색, 카메라 업로드

## 6. 운영상 필수 기능

- 중복 일정 통합
- 공식 출처와 최근 수정일 표시
- 우천·취소·장소변경 긴급 공지
- 식품·위생·안전 관련 체크리스트
- 환불정책 사전 고지
- 실제 참여자 중심 후기권한
- 개인정보·광고·전자상거래 고지
- 관리자 감사로그와 수정이력
